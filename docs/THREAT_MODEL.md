# Threat model

## Assets

Original uploaded files, extracted text, annotation proposals/corrections, verified gold labels, reviewer decisions, release manifests, JWT signing secret, database credentials, job state and audit history.

## Trust boundaries

Browser/API; API/SQL database; API/filesystem asset store; API/Redis queue; worker/provider runtimes; untrusted uploads/parsers; optional third-party model checkpoints and gated model services.

## Threats and mitigations

| Threat | Mitigation in this build | Remaining concern |
|---|---|---|
| Path traversal | Display filename reduced to basename; storage path generated by THEO | Parser libraries still process untrusted bytes |
| Oversized upload | Per-file size limit while reading | No global request quota or archive bomb controls |
| Duplicate ingestion | SHA-256 deduplication within dataset | Cross-dataset deduplication is not enabled |
| SQL injection | SQLAlchemy ORM and parameterized statements | Database credentials and network must be protected |
| Unauthorized API writes | Scrypt passwords, expiring HS256 tokens, admin/reviewer/viewer roles; Compose enables auth gate | Local mode defaults to no auth; no SSO/MFA/session revocation list |
| Token compromise | Secret from environment, one-hour expiry, active-account lookup | Secret rotation invalidates outstanding tokens; use secret manager |
| Malicious uploads | Extension allowlist, size limit, isolated path | No antivirus scan/content disarm; deploy additional scanning and worker sandboxing |
| Cross-origin abuse | Configurable CORS origins | Set exact trusted origins for deployed environments |
| Job loss | Optional Celery/Redis, late acknowledgement and retries | Need dead-letter strategy, queue monitoring and recovery drills |
| Model/data leakage | Models are opt-in; no default remote API calls | Review model terms, outbound network, privacy and data residency before enabling |
| Release tampering | Content hashes, release freeze through API | Privileged DB/storage administrators can alter content; use external backups/integrity logs |
| Resource exhaustion | Upload limits and sampled video frame cap | Add per-user quotas, CPU/GPU limits and rate limiting before public exposure |

## Deployment guidance

Local launcher binds to loopback. Docker Compose enables authentication and role restrictions, PostgreSQL, Redis and Celery. Before public exposure, add HTTPS, hardened reverse proxy, exact CORS origins, rate limits, upload scanning, isolated workers, secret management, database/object-store ACLs, backups, retention controls, vulnerability scanning, monitoring and security review. Do not process regulated or confidential data without a documented privacy/legal basis and approved model/data path.
